# 子待办是拆出来的步骤，不是嵌套的待办

一件事太大，想在它肚子里列几步「先干这个、再干那个」。本决定把子待办定为父待办的**内部结构**：**归属分类跟着根走、没有自己的计划日、不上沙漏轴、不进未排期列、不占徽标的数**；层级任意深，子待办自己还能再拆。两轴世界观原封不动——「一条待办 = 轴上的一个点」说的从此只是顶层。

勾在父子之间**完全解耦**：子全勾完不推父，勾父不连子——这个 app 里「完成日是被打勾的那一天」，勾是人做的记录，不是推导出来的状态；替人写勾（子推父）与伪造记录（父带子）都拒绝。齐不齐、勾不勾，人自己看。

**露面**：子树**常开**，摊在父行底下缩进一档，三处（分类视图两列、轴、未排期列）一个样——「哪几件事只在哪一屏能做」是 ADR-0003 拆过的那类规矩，不再立。第一版做过「默认收起、进度记号『3/5』兼展开入口、树尾常驻『添一步』」，上手一天即撤：树摊开着，折叠是多出来的一道手续，进度数字与眼前的步骤重复，常驻追加行是每棵树尾的噪点——加步骤走右键「添加子待办」，点了才浮出一行输入。**子行的权能**：打勾、删除、改写、拖拽四样照旧；排期入口与「移到分类」两格**空着**——不是禁用，是无此事，沿用「三处的行同一副结构，差别只在哪几格是空的」。

**树的流动**：升级、降级、树内换爹双向全通，本质都是「把节点挂到新位置」这一件事（`Store` 里一站 `relocate` 管到底）。手势按落点分两件事：**落在两行之间的缝里是换位置**（缝在哪层挂哪层，顶层的缝就是升级的落点），**落在一行身上是入怀**（成为它的末子）；右键菜单与 Mac 改写中的 Tab（缩进）/Shift+Tab（升一级）是并行入口。挂进怀里顺手撤掉排期——「步骤不单独排期」的直接推论，不算「一次动了两样」。位置（`order`）的可比范围从「同分类」收窄到「同一窝兄弟」。新子生在兄弟末尾——步骤是按 1、2、3 写的，与顶层「新记的落最上面」刻意不同。

**删父连子**：删父给整棵子树打同一个删除时刻，一扇窗口、一起去、一起回；先前单独死的带各自的时刻，各归各的窗口。「非空分类删不掉」不照搬到父上——分类删不掉是因为几十条一起进删除态看不清丢了什么，而一棵树是这件事自己的几步，删除意图明确、一撤全回。

## Considered Options

- **子待办是真待办（各有计划日、各自上轴）** —— 拒绝：轴上会出现脱离父上下文的「半条事」，沙漏、未排期、过期记号全得重新回答「子待办算不算数」，复杂度全数回笼。
- **只允许一层** —— 被使用者否决：任意嵌套。
- **勾父连子 / 子全勾完推父** —— 拒绝：见上，勾是记录不是推导。
- **删非空父拒绝（照搬分类）/ 删父孤儿升级** —— 拒绝：前者把日常的「这事取消了」变成先拆树的苦役；后者让删除凭空制造顶层待办。
- **大纲式横向缩进拖拽** —— 拒绝：两列布局里施展不开，iOS 自绘拖拽也没有连续横向判定的容身处。

## Consequences

- **第二条不变式，与「活着的待办，分类必须活着」并排：活着的子，父必须活着。** 哪条路救活一条待办，祖先链跟着复活（只救链上节点，不连带陪葬的兄弟）；同步冲突里它表现为「子胜、父复活」——这台删父、那台改子/加子，父复活记账推回云端。
- **同步的「挂靠」并进 placement 方面**：分类 + 父 + 第几位是一件事，拆开会合出「挂着 A 的父却在 B 的分类里」。跨记录的形状（两台互相入怀合出的环、子带着陈旧分类）在落地后修圆：环断在刚落地的那条（升它到顶层），分类随根正；修补是本地的表态，记账推回云端，两台各修各的、修出来一致。
- **孩子等父落地**：云端先送来子、父还没到，与「待办等分类」同一个孤儿池候着，父一落地一层层接回。
- **归列只看顶层**：分类视图左右列、轴、未排期列铺的都是顶层；子待办打了勾不迁列，父完成了整树随父行去右列。「非空分类删不掉」数的是每一条活着的记录——步骤也是记录。
- iOS 这一版欠着（都写在 `SubTodoTree.swift` 头上）：入怀与升降级等自绘拖拽那一轮；添步骤没有入口——Mac 走右键，iOS 的长按菜单总开关关着，等磨玻璃那一轮一并回来。

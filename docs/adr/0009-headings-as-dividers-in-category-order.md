# 小标题是手排顺序里的一道分界，不是装待办的容器

一个分类里的事多了，想再分几节看。本决定把**小标题**定为分类视图左列手排顺序（ADR-0002）里的**一道分界**：它像一行那样站在顺序里，它下面、到下一个小标题之前的顶层待办就是这一节。节没有容器、待办身上不记「属于哪一节」——归节就是拖到那一节里，用的就是现成的拖拽换位。

**存法**：小标题借待办的记录存，多一个「是小标题」的记号（本地 JSON 与云端记录都只在小标题上写这个键）。它要站进同一条顺序里，而位置、同步的挂靠方面、删除记号与撤销窗口、就地改写、「先有行、后有字」的新行，待办身上全都现成。代价是 `Store` 里每条「待办才有的本事」都要挡一下小标题：打勾、排期、换分类、拆步骤、入怀都不接，徽标、轴、未排期列、右列都不算它。

**露面**：只在分类视图左列。右列按完成日排，是记录，不分节；打了勾的待办位置留着，取消打勾回到它原来那一节。轴与未排期列横跨各分类，节在那儿没有意义，不显示。样子是分类色胶囊，与未排期列的组头同一副——胶囊在 app 里本就意味着「一组的开头」。不折叠、不计数，理由与子待办那一轮撤掉折叠和进度记号相同（ADR-0008）。

**几条规矩**：

- 顶上不带标题的那一块是落脚处：记事栏新记的、从别的分类移来的，照旧落在左列最上面，也就是第一个小标题之上。它永远在最上面，小标题挤不到它上头去。
- 待办落在小标题**身上**，成了这一节的第一条——小标题没有怀；子待办落上来随之升到顶层。
- 拖小标题，**整节跟着走**（已完成的、占位的都算这一节）。一节只能落在节与节的交界上：落进别人那一节的半中间，按挪动的方向吸到最近的交界——往上吸到那一节前头，往下吸到后头——免得把别人那一节拦腰截走后半截。
- 删小标题只删这道分界：下面的待办一条不动，并入上一节。照旧走删除记号与撤销窗口。
- 小标题生下来是什么就一直是什么，不与待办互相转换。
- 「非空分类删不掉」数的是每一条活着的记录，小标题也拦（与 ADR-0008 里「步骤也是记录」同一个道理）；提示把待办与小标题分开报——小标题的疏通路子只有删掉。
- 新建：Mac 上右键左列一行「在上方加小标题」，或右键左列空白处「加小标题」（落在末尾）。改名单击，回车收下并在这一节顶上开一行新待办。

## Considered Options

- **待办记住自己属于哪个小标题（容器式）** —— 拒绝：右列可以跟着分节，但删小标题时那些待办归谁、两台设备一边改归节一边删标题怎么合、手排顺序在节内节外怎么比，都要另立规矩；而分界式只要一个记号，顺序、同步、撤销全是现成的。真想让右列也分节时再回来翻这一条。
- **小标题另立一种记录** —— 拒绝：它要与顶层待办插在同一条顺序里比位置，另立记录就得让两种记录共用一套位置、同步再多一种类型，换来的只是模型上的干净。
- **小标题可以折叠、带计数** —— 拒绝：同 ADR-0008 撤掉折叠与「3/5」的理由。
- **二级 tab（一次只看一节）** —— 拒绝：分类视图的本意是同屏可见，藏起其余几节就是多出一条要记的规矩。

## Consequences

- 节只由位置决定，所以凡是改顶层顺序的路都可能顺带换节：沙漏视图未排期列里在同一个分类组内拖着换位，会在看不见小标题的地方把一条待办换到另一节。罕见且无害（换回来再拖一次），不为它在那一列画小标题。
- 两台设备同时重排同一个分类时，ADR-0002「合出来的顺序确定、但可能哪边拖的都不是」的分寸照旧，节也跟着这个顺序走。
- 旧客户端（没有这个记号的版本）读到小标题会当成一条普通待办。两端同一份代码一起更新，不另做兼容。
- iOS 这一版欠着两件，记在 `CategoryScreen.swift` 的 `HeadingRow` 头上：新建的入口跟长按菜单那一轮一起回来；拖小标题整节跟着走等自绘拖拽那一轮——「悬到哪当场换到哪」的活重排拖着一整节，得等落点能吸到交界上再做。iOS 上看得见、改得了名、删得掉，拖着的待办越过它就换节。

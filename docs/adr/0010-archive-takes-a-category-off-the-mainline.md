# 归档把一个分类连同名下的一切从主线上撤下，待办一条不动

一个分类告一段落了（项目做完、旅行回来），留着它，tab 栏一天天变挤；删掉它，又得先把里头的记录一条条清空（「非空分类删不掉」）——想要的其实是「收起来，记录留着」。本决定加一个**归档**：在分类上打一个归档记号，它连同名下的一切从主线上撤下，只在**档案**里看得见；**取回**就原样回来。

**撤下的范围**：tab 栏、沙漏轴（做完的、没做完的都不上）、未排期列、侧边栏徽标、记事栏的分类选择器、「移到分类」的名单。都由 `Store` 一处判（`mainlineCategories` 与轴、未排期列、徽标的过滤），视图层不自己滤。

**不动的**：待办一条不改 —— 计划日、完成状态、顺序、子树、小标题全都原样。归档只是分类身上的一个方面，与改名、换色、挪位、删除并列。所以它不违背「横轴上的移动不碰纵轴」：轴上撤下的是**露面**，不是日子。

**几条规矩**：

- 里头有没做完的也收：跟着一起撤下，取回时原样回来。不拦、不确认。
- 不开撤销窗口：归档没丢任何东西，档案本身就是回头路。收进去的那一下档案盒跳一拍，交代它去了哪儿。
- 取回回到 tab 栏原来那一格：分类在数组里的位置从来没动，tab 栏只是不画它 —— 那个位置是使用者自己拖出来的。
- 档案盒钉在 tab 栏最末（「+」右边），有归档的才露面。点开是档案名单，最近归档的在最上面；点一个，内容区就是它的分类视图 —— 同一副，行上能做的事一件不少，顶上多一行「归档于 X · 取回」，盒子是选中态。
- 在档案里做的事留在档案里：记一条、取消打勾，都不会让它自己回到 tab 栏。回去只有「取回」一条路。档案里的待办拖到上面的 tab 上、或「移到分类」，就是单捞一条出来。
- 正看着的那个被归档，落回沙漏。记事选择器记着的那个被归档，先落回主线上的第一个；记性不抹，取回之后又认回它。主线上一个分类都不剩时不回引导页（分类还在，只是都在档案里），沙漏屏的输入区换成一句「新建一个，或从档案取回」。
- 删除的规矩不变：档案里非空的分类照样删不掉。删分类被拦下的提示补一句「只是不想让它占着 tab 栏，可以归档」—— 这正是先前缺的那条路。在档案里删掉的，占位留在档案名单它那一行。
- 归档是数据，不是偏好：随同步走，两台设备看到同一条 tab 栏。

## Considered Options

- **只收做完的（有没做完的就拦下）** —— 拒绝：多一步清理，而归档本就可逆、不丢东西；代价是排了期的事会跟着从轴上撤下，这是使用者自己选的收法。
- **做完的仍留在轴上（归档只动 tab 栏）** —— 拒绝：轴的过去那段照旧挂着收起来的那些事，「收起来」就只收了一半；想看已完成，取回或去档案里翻。
- **侧边栏第三项「档案」** —— 拒绝：iOS 没有侧边栏，两端就不同构了；档案盒在两端都是 tab 条末端同一个位置。
- **右键菜单里列「已归档的分类」直接取回** —— 拒绝：不加控件，但只能取回、翻看不了。

## Consequences

- 同步只多一个方面（`archivedAt`，与名字、颜色、位置、删除记号并列合并）：一台归档、一台改名，两边都保住；一台归档、一台取回，后写的算。归档对待办没有约束，不需要新的冲突规矩。
- 新字段上生产环境前，要在 CloudKit 控制台把开发环境的 schema 部署到生产一次。旧版客户端认不出这个字段，会照常显示归档的分类；两端同一份代码一起更新，不另做兼容。
- 档案里的分类改名、换色先取回再说：那两块面板从 tab 上弹出，档案名单本身是个浮层，浮层上再叠浮层收起来就乱了。档案名单上只有取回与删除。

# 「过期」立为概念，但只是一个安静的记号

ADR-0001 立下「不存在过期」时，把三个东西捆在一起否决了：过期这个概念、置顶催办的机制、以及视觉上的任何区分。用了一段时间后发现捆错了 —— 「计划日在过去而未完成」这个状态真实存在，扫一眼认不出它，漏掉的代价也真实发生；而当年真正想扔掉的只是催促感。本决定把这三样拆开：**概念立起来，视觉给一个弱记号，催办机制仍然禁止。**

口径：**未完成，且计划日在「今天」之前**（按天比，取 `TodayClock` 的今天）。当天不算 —— 今天还没过完；已完成的不算，哪怕完成得再晚 —— 打勾那一下顺手把记号抹掉；未排期的没有计划日，谈不上过没过。不分拖了多久 —— 档位本身就是一种催促。派生判断（`TodoItem.isOverdue(today:)`），不落盘。

记号：**那一行的勾圈描边换成琥珀**，三处的行同一副（未排期列天然没有）。过期是「未完成」的一层状态，而完成状态从来由圈说（灰 / 分类色 / 青），把它也交给圈是顺着既有语法多说一个词。琥珀单独一档色值（浅色外观 `0xC2801F`、深色外观 `0xD9A558`），刻意不取分类色板里的 amber —— 那是某个分类的记号，撞了色就分不清「属于琥珀色的分类」和「过期了」。

## Considered Options

记号的形态，四案对比后取琥珀圈：

- **虚线圈（不加色）** —— 拒绝：16px 下几乎看不见，且虚线在系统语言里惯常说「禁用 / 占位」，语义误用。
- **行首小点** —— 拒绝：行结构从此多养一个第七件部件，且小得像灰尘 —— 记号可以弱，不该弱到要人找。
- **左缘细条** —— 拒绝：警示条（severity stripe）的血统，四案里最像催办。
- **维持 ADR-0001 原判** —— 拒绝：漏掉旧安排的代价已经付过几次，「产品不提供任何提醒机制」这半句被实践推翻。

## Consequences

- ADR-0001 被部分修订：「不设过期概念」作废；「不置顶、不自动顺延、一条连续的轴」全部仍然有效。
- 琥珀成为一屏上第二种功能色（青之外）。积压多时过去的日子里会立起一列琥珀圈 —— 接受，这正是「安静但诚实」的分寸；不为此分档、不为此淡化。
- 词汇表里「截止日 / 到期日 / DDL」照旧 Avoid，理由换了：那些词把计划日说成承诺，而这里的过期只是事实陈述，不是违约。

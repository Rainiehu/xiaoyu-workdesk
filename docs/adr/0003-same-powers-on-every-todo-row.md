# 一行待办能做什么，不看它在哪一列

改写正文与改归属原本只属于分类视图：轴上和未排期列的行只能勾、能排、能删。现在**三处的行本事一致** —— 单击整行就地改写、右键「改写」与「移到分类」、拖到 tab 栏换分类，在哪一列都是同一套。

这么改是因为原来那条界线是从实现角度划的，不是从使用角度：沙漏视图是打开主线默认落地的那一屏，也是最常盯着的一屏，在那儿看见一句话写错了却得先切到某个分类去改，这一趟没有道理。而「哪几件事只在分类视图里做」本身就得记，记不住就会去点，点了没反应 —— 一条要人记住的规矩，抵不上它挡下的那点麻烦。

## 推翻了什么

`CONTEXT.md` 里原有三条说法作废：

- 「改写正文和移到分类只在分类视图里」—— 理由是改写要把整行变成输入框，而轴上的行右边挤着完成日和分类 tag，会把行撑变形。实测不成立：改写时让开的是删除按钮，与分类视图里一样，其余各格原地不动。
- 「归属只在分类视图里定」「跨分类的拖拽根本不存在」—— 这两条在写下之后就已经不是事实了。分类 tab 的落点接的是 `DraggedOntoTab`，它把 `DraggedTodo` 也收了进去，而轴上和未排期列的行本来就在拖 `DraggedTodo`。从轴上拖一行到 tab 上换分类一直是能用的，只是文档还在说它不存在。

## Consequences

- 改写、移到分类、删除、打勾、拖拽这五件事，三处完全一样。**唯一还看列的**是排序：只有分类视图左列能拖着换位置（见 ADR-0002），因为「位置」只在一个分类里可比。
- 就地改写这段行为（改不改、草稿是什么、Esc 放弃、失焦即提交、空白不算改）与「移到分类」的菜单都收进 `TodoRowStyle.swift`，三处照着来 —— 三份抄写迟早会漂成三副脾气，这正是当初把行的结构收到一处要防的事。
- 单击整行从此都是「进改写」。轴上和未排期列原本单击没有任何反应，多出这一下会有误触的余地；换来的是「点一行就能改」在哪儿都成立。
- 已完成的行照样改得动，与分类视图右列一致。
- 沙漏 tab 不接落点，往它上面拖待办什么也不会发生 —— 它不代表任何分类，没有「归到沙漏」这回事。

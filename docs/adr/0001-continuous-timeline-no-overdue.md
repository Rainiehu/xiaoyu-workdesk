# 用一条连续时间轴取代「今日 / 历史」，且不设过期概念

> **部分修订于 [ADR-0004](./0004-overdue-as-a-quiet-mark.md)**：「不设过期概念」这一半作废 ——
> 过期立为概念，行上有一个安静的琥珀记号；「不置顶、不自动顺延、连续的轴」这一半仍然有效。

初版把待办按创建日切成「今日待办」和「历史」两个视图，未完成的旧待办会冒泡成「早前未完成」置顶催办。我们改为一条按**计划日**铺开的连续时间轴（沙漏视图）：今天锚定在中间，上方是过去、下方是未来，自由滚动；计划日在过去而未完成的待办就安静地留在原处，不置顶、不变色、不自动顺延。

这么做是因为「今日 / 历史」这个切分把同一条时间轴人为断成两截，而「早前未完成」置顶会让积压的旧事持续挤占最显眼的位置。一条连续的轴同时承担了原来两个视图的职责，也让「过去」重新变成可以平静回看的东西而不是待清算的债。

## Considered Options

- **过期项置顶 + 一键挪到今天**（初版行为的延续）—— 拒绝：这正是我们想去掉的催促感。
- **过期自动顺延到今天** —— 拒绝：会丢失「本来安排在哪天」和「拖了多久」的信息。
- **双向时间轴但过期项仍高亮** —— 拒绝：与「不设过期」的取舍自相矛盾。

## Consequences

- 计划日在过去的未完成待办**可能被漏掉**，产品不提供任何提醒机制。这是接受的代价。
- 已完成的待办落在它的**计划日**而非完成日，所以打勾不会让条目跳到别的日期；实际完成日另用小字标注。
- 计划日、完成日、创建日必须是三个独立存储的字段。初版用创建日兼作计划日（`moveToToday` 直接改写创建时间）的做法被废弃。

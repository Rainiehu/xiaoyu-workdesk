# 分类视图左列的顺序归使用者自己拖，日期只作初值

分类视图的左列原本由日期排定：已排期的在上，按计划日从早到晚；未排期的在下，按创建日从新到旧。现在改为**由使用者自己拖出来的顺序**：待办多存一个「位置」字段，左列照它铺；拖着一行放到另一行上，那条就落到目标那个位置，其余的依次让开。原来那套日期规则退成初值 —— 升级上来的旧数据照它补一遍位置，此后不再介入。

这么做是因为「哪件先做」是分类视图里唯一要紧的问题，而它不等于「哪件排得早」：手头的优先级常常和日历无关。两种顺序不能同时说了算，所以让人排的那个赢；日期在这一列里本来就是刻意弱化的（行尾一个次要标签），把它同时当作排序依据与这条取舍自相矛盾。

## Considered Options

- **保留日期排序，手动排序只在段内生效** —— 拒绝：拖过段界的那一下会莫名弹回，规则说不清楚。
- **手动排过的置顶成一块，其余仍按日期** —— 拒绝：把第 5 条拖到第 7 条的位置，它却窜到顶上，与手势的意思相反。
- **不加字段，用 `todos` 数组的顺序当显示顺序** —— 拒绝：那个数组同时是沙漏视图里同一天内的先后，一次拖动会顺带改掉另一条轴上的东西。

## Consequences

- 已排期与未排期不再分成上下两段，混在同一列里，靠行尾日期标签的有无区分。
- **排期与改期不再改变左列的位置**，包括在沙漏视图里把条目拖到别的日子。两条轴因此彻底不交叉：纵轴的动作不碰这一列的顺序。
- 新记下的待办落在左列**最上面** —— 刚想到的事就在眼前，不满意再拖走。
- 打勾离开左列时位置留着，取消打勾就回到原处。
- 右列不由人排，仍按完成日从新到旧：那是一份记录，不是一张待排的单子。
- 位置只在同一个分类里可比。待办移到别的分类时位置作废，落在新分类的最上面。
- 旧数据（没有这个字段）在载入时按老规矩补一遍位置并落盘，升级前后第一眼看到的顺序一致。
